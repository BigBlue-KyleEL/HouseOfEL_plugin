## Server authority and unchanged rules

A server-held session binds each offered action to its callback and current player. Each opening has a unique screen ID. Unknown, stale, closed, replaced, disconnected or repeated clicks cannot apply an outcome. Client-supplied NPC IDs, levels and choice values are ignored. A selected session is consumed before its callback, preventing duplicate recruitment/cost application.

Milestone callbacks resolve the current NPC and use the existing `MilestoneChoiceService`. The service rechecks owner, current specialization/level, the registered option and L8 parent at click time, then uses the unchanged first-pick/current-choice/respec chain. First choice remains free, current choice is a no-op, respec costs 200 spendable Toil after the existing seven-day cooldown. These guards also protect delayed Paper/Form callbacks; valid choices and costs remain unchanged.

Recruitment captures the server location/options and rechecks the existing spawn permission before invoking the unchanged `recruitHelper` cost-and-spawn path. The later feedback guard blocks new Lumberjack/Farmer recruitment; progression and existing Helpers remain unchanged.

Core’s screen-close handling now removes only the matching screen ID. A delayed close notification from an older screen cannot invalidate a newer fork. Session state is cleared on disconnect; closed-screen callbacks remain inert, and the next opening replaces the cached session.
